# TASK-004-008 Implementation Issue

Status: RESOLVED

## Task ID

TASK-004, TASK-005, TASK-006, TASK-007, TASK-008

## Issue

The implementation plan does not define API methods, paths, response bodies,
HTTP statuses, or an error format. The second-stage login request also lacks
the user or transaction correlation value needed to safely scope a temporary
code. The post-verification authentication mechanism is undefined.

## Existing Behavior

The repository has no application controllers, authentication state, or API
contract.

## Plan Definition

TASK-004 through TASK-008 require controllers, error mapping, temporary-code
correlation, authenticated operator context, and a logout response contract.

## Why Implementation Cannot Continue

Implementing these tasks now would require inventing externally visible API
behavior and authentication rules that are explicitly listed as open questions
in the reviewed implementation plan.

## Suggested Area To Review

Please define the API contract, temporary-code correlation and lifecycle,
post-verification authentication mechanism, logout placeholder response, and
admin-to-admin permission behavior. System Design will then update the
affected task statuses to PLAN UPDATED.

## System Design Review

The updated requirement confirms HTTP methods: registration, first-stage
login, second-stage verification, logout, and user listing use POST;
permission update uses PUT. This resolves only the HTTP-method portion of the
issue.

The requirement and Gherkin files still do not define endpoint paths, request
and response contracts, temporary-code attempt correlation, or
authenticated-state behavior. These gaps prevent a controller, Redis key
design, or authorization dependency from being designed without inventing
business rules.

The implementation plan was updated on 2026-09-15 to reflect the confirmed
methods and existing foundation code. TASK-004 through TASK-008 remain
`DOUBLE CHECK` and must not be implemented until PM supplies the remaining
clarification recorded in the plan's "PM Clarification Required" section. On
PM confirmation, System Design must update only the affected tasks to
`PLAN UPDATED`, clear their development and code review dates, resolve this
issue, validate the plan, and request review.
