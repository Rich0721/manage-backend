# BXL-004 Code Review

Status: OPEN

## Review Result

- **P1／提交後標籤快取發布失敗，未使兩個快取失效。**
- **P2／批次寫入失敗訊息未依操作與商品識別。**

## Implementation Plan

§5.2 要求商品寫入失敗時回傳新增商品名稱或修改商品 ID 的指定訊息；§5.3 要求 DB 已提交但任一快取發布失敗時，失效可能過期的 key，並回 503。

## Existing Implementation

`src/services/product_service.py:250` 在 DB commit 後呼叫 `LabelCacheRepository.replace()`；`__write_batch()` 的 `except` 未處理 `LabelCacheRepositoryError`，外層 `batch_products()` 才將它轉成 503。`:447-449` 將新增商品的主鍵衝突轉成通用資料錯誤；`:270-277` 也使用通用新增資料錯誤。

## Review Issue

若新分類已隨商品提交，而標籤快取發布失敗，原 `product:labels` key 仍可保留舊內容。已失效的 `products:info` 下次冷載入時會取到舊標籤快取，無法為新商品建立完整快照；計畫要求的提交後雙 key 失效路徑沒有執行。另在單列新增主鍵衝突時，對外訊息為 `新增商品資料錯誤，請檢查Excel內容`，不是需求指定的 `新增<商品名稱>失敗，請檢查Excel內容`。請一併檢查修改商品寫入失敗的訊息。

## Expected Behavior

任一快取在 DB commit 後發布失敗時，應依 §5.3 失效可能過期的快取並回 503。批次商品寫入失敗需 rollback，且對外訊息符合 §5.2 的新增名稱／修改 ID 規則。

## Suggested Area To Fix

檢查 `__write_batch()` 的提交後例外分類、快取失效與 `__batch_product()` 的逐列寫入錯誤映射；補上故障注入測試。
