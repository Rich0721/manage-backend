# BXL-003 Code Review

Status: RESOLVED

## Review Result

- **P2／文字欄位的 Excel 公式與錯誤儲存格未拒絕。**

## Implementation Plan

§5.2 與 §7 BXL-003 要求驗證 Excel 公式及錯誤儲存格，錯誤資料需回傳對應分頁的 400 訊息。

## Existing Implementation

`src/services/product_excel_service.py:119-125` 只取 `cell.value`，未保留儲存格型別；`:194-195` 將商品名稱與分類交給 `__text()` 轉成文字。

## Review Issue

以 `Add Product` 的商品名稱 `=1+1` 建立實際 `.xlsx` 後，`ProductExcelService.parse()` 接受該列並回傳名稱 `=1+1`。錯誤儲存格若落在文字欄位，也可能被當成一般名稱或分類。這讓不符合格式的內容進入交易。

## Expected Behavior

指定分頁資料列中的公式與錯誤儲存格應依分頁回傳 `新增商品資料錯誤，請檢查Excel內容` 或 `修改商品資料錯誤，請檢查Excel內容`，不得寫入商品或標籤。

## Suggested Area To Fix

檢查 `.xlsx`／`.xls` 讀取時保留的儲存格型別與逐列驗證，補上兩種格式可驗證的錯誤情境。

## Resolution

Status: OPEN（2026-10-14 複審）。原問題已修正：`.xlsx` 保留公式／錯誤型別並拒絕；`.xls` 的錯誤型別及已辨識的公式記錄亦轉為無效儲存格。仍有以下新增的實作問題：

- **P2／合法的傳統 `.xls` 檔可能被判成格式錯誤。** `src/services/product_excel_service.py:174-177` 的公式掃描固定以 `CompDoc` 開啟並只讀 `Workbook` 串流；本專案安裝的 `xlrd/book.py:633-649` 除了 `Workbook`，亦接受 `Book` 串流與原始 BIFF 檔。這兩類檔案可通過前面的 `xlrd.open_workbook()`，卻在公式掃描階段失敗或取得空串流，回傳 `檔案格式不正確，請上傳Excel檔案`，違反 BXL-003 的 `.xls` 上傳支援。請讓型別掃描與 `xlrd` 接受的傳統檔格式一致，並用實際檔案驗證。

## Second Review（2026-10-14）

Status: OPEN。`Workbook`／`Book` 串流選取及原始 BIFF 讀取已修正；BIFF5 工作表名稱解析仍會漏掉公式：

- **P2／BIFF5 `.xls` 的公式儲存格可能被當成一般資料。** `src/services/product_excel_service.py:198-209` 一律將 BOUNDSHEET 的第 8 個位元組當成 BIFF8 Unicode 選項，並從第 9 個位元組開始解碼名稱。`xlrd/book.py:755-758` 對 BIFF5 則從第 7 個位元組讀取單位元組長度，名稱從第 8 個位元組開始。公式掃描得到的分頁名稱與 `xlrd` 回傳的 `Add Product`／`Update Product` 不同，`__read_xls()` 依名稱查詢時便找不到公式位置。用 BIFF5 BOUNDSHEET 加 FORMULA 記錄進行唯讀複驗，公式掃描有一個座標，但 `Add Product` 鍵不存在。這違反計畫 §5.2 對公式儲存格的拒絕規則。請依 BIFF 版本解析 BOUNDSHEET，並確認 BIFF5 的公式落在指定分頁時回傳對應 400 資料錯誤。

## Third Review（2026-10-14）

Status: RESOLVED。掃描器現在依 BOF 版本區分 BIFF5 與 BIFF8 的 BOUNDSHEET 名稱格式；BIFF5 從正確的位移取名稱，再依對應分頁標記公式儲存格。測試用可由 `xlrd` 解析的 BIFF5 位元組驗證正常匯入及公式／錯誤儲存格拒絕，先前的公式漏檢已處理。
