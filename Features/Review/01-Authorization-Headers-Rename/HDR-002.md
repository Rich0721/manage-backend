# HDR-002 Code Review

Status: RESOLVED

## Task ID

HDR-002（2026-10-08 Headers Rename）

## Review Result

需要補足 HTTP 與 JSON 身分衝突的回歸測試。封套改名與目前 controller 資料流符合計畫；缺口屬 Test Review Problem。

## Implementation Plan

`Features/Plan/01-Authorization-Headers-Rename.md` 的 HDR-002 要求：JSON `headers` 可選、舊 `header` 回 422，且 JSON `headers` 的 `Uid`／`Authorization` 不得覆寫實際 HTTP 身分；測試須涵蓋衝突情境。

## Existing Implementation

- `src/models/schemas/user.py` 將 `UserEnvelope.header` 改為 `headers`，沿用 `extra="forbid"`。
- `src/controllers/user_controller.py` 的 `build_envelope()` 輸出 `headers`；受保護 route 仍由 FastAPI `Header` 讀取 HTTP `Uid`／`Authorization`。
- `tests/controllers/test_user_controller.py` 已測 JSON 偽造身分但缺 HTTP 身分的情境，以及 HTTP 身分有效但 JSON `headers` 省略的情境；沒有兩者同時存在且值衝突的案例。

## Review Issue

位置：`tests/controllers/test_user_controller.py` 的 `test_get_users_does_not_use_json_header_as_authorization()` 及 protected request 測試。

現有案例未直接驗證當 HTTP `Uid`／`Authorization` 與 JSON `headers` 不一致時，送往 `UserService` 的 `AuthorizationObject` 仍只包含 HTTP 值。這是 HDR-002 明列的授權來源隔離測試，現有 255 passed 無法取代該斷言。

## Expected Behavior

同一個受保護請求同時帶有不同的 HTTP 與 JSON 身分時，controller 只將 HTTP `Uid`／`Authorization` 傳給 service；JSON `headers` 不得覆寫或補足它們。既有成功、缺身分與舊欄位拒絕行為維持。

## Suggested Area To Fix

在 `tests/controllers/test_user_controller.py` 補上 HTTP／JSON 值衝突的 API 測試，確認 service 接收到的身分，以及回應使用新版封套。無需改動既有授權規則。
