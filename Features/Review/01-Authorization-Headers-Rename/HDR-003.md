# HDR-003 Code Review

Status: RESOLVED

## Task ID

HDR-003（2026-10-08 Headers Rename）

## Review Result

需要修正 Product 授權來源測試的判定方式。Product schema 改名及四條成功 route 的 JSON 輸出符合計畫；缺口屬 Test Review Problem。

## Implementation Plan

`Features/Plan/01-Authorization-Headers-Rename.md` 的 HDR-003 要求：三條有 body 的 API 可接收或省略 JSON `headers`、舊 `header` 被拒絕；JSON 偽造身分不能授權，HTTP／JSON 身分衝突時只將 HTTP 值交給 service。

## Existing Implementation

- `src/models/schemas/product.py` 將 `ProductEnvelope.header` 改為 `headers`，保留 `dict[str, str]` 及 `extra="forbid"`。
- `src/controllers/product_controller.py` 沿用 HTTP `Header` 依賴及共用 `build_envelope()`，無需改寫。
- `tests/controllers/test_product_controller.py` 的 `test_add_product_does_not_use_json_header_as_authorization()` 只送 JSON `headers`，沒有實際 HTTP `Uid`；該 route 的 `UidHeader` 本來就是必填，因此 422 即使 JSON 欄位驗證失敗也會出現。

## Review Issue

位置：`tests/controllers/test_product_controller.py` 的 `test_add_product_does_not_use_json_header_as_authorization()`。

目前 `422` 與 `service.add.assert_not_awaited()` 不能證明 JSON `headers` 已被接受，也不能證明它不會覆寫有效的 HTTP 身分。新增 `headers` 欄位的契約與 HDR-003 指定的 HTTP／JSON 衝突驗收因此沒有被有效測試。

## Expected Behavior

有效的 HTTP `Uid`／`Authorization` 與相衝突的 JSON `headers` 同時存在時，請求應通過封套解析，service 應只取得 HTTP 值；舊 JSON `header` 仍回 422，Product GET 仍不需 body。

## Suggested Area To Fix

在 `tests/controllers/test_product_controller.py` 補上有效 HTTP 身分與相衝突 JSON `headers` 的案例，明確驗證 service 參數與新版回應封套；檢查 add／update／delete 三條 body route 的新欄位接受情況。既有 Product controller 無需因本 Review Issue 修改。

## Resolution

```text
Status: RESOLVED

Implementation Status: DONE
```

2026-10-08 複審：addProduct 以有效 HTTP 身分及相衝突的 JSON `headers` 成功回應，service 收到 HTTP 值；updateProduct／deleteProduct 也接受新版欄位並確認 service 使用 HTTP 值。原僅送 JSON 身分及舊 `header` 的 422 測試仍保留，GET 維持無 body。User／Product controller 相關測試 33 passed；Programmer 記錄的完整回歸為 255 passed、7 skipped。原 Review Issue 已解決。
